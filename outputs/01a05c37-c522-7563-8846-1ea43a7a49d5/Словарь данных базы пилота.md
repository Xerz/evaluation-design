# Словарь данных базы пилота автоматизации критериев ТюмГУ

## Назначение

База фиксирует измерительный контур пилота: 26 критериев, инструменты и их версии, доступные типы данных, условия A0–A5, эффекты E1–E9, способы проверки и будущие результаты. Она не является системой рейтинга преподавателей.

Главная единица машинного результата — доказательный фрагмент с источником, таймкодом, обоснованием и неопределённостью. Балл 0 не используется для обозначения отсутствия данных или ошибки.

## Слои модели

### Справочники и происхождение

| Таблица | Назначение |
|---|---|
| `source_documents` | Источники формулировок и дизайна с SHA-256. |
| `criteria` | 26 критериев в исходном порядке, с блоками и подблоками. |
| `research_sources` | Научные публикации, методики и обзоры: полная ссылка, DOI/URL, тип исследования, краткое доказательство, доступность и статус проверки. |
| `criterion_research_sources` | Редактируемая связь публикации с критерием: роль доказательства, статус релевантности, поддерживаемый тезис, локатор и комментарий. |
| `criterion_score_levels` | Три точных описания шкалы 0–2 для каждого критерия. |
| `data_types` | Типы записей, транскриптов, материалов, опросов, результатов и метаданных. |
| `criterion_data_requirements` | Прямые и дополнительные источники, без которых конкретный критерий нельзя установить. |
| `instruments` | Четыре сравниваемых инструмента. |
| `instrument_versions` | Версии, конфигурации, статус жизненного цикла и ограничения. |
| `instrument_version_data_types` | Обязательные, дополнительные и производные данные версии. |
| `instrument_version_criteria` | Покрытие критерия конкретной версией и статус валидации. |

| Таблица | Назначение |

| `comparison_conditions` | A0–A5. |
| `condition_instruments`, `condition_data_types` | Состав инструментария и данных каждого условия. |
| `effects` | E1–E9. |
| `verification_methods` | T1–T9 с метриками и процедурой. |
| `verification_method_research_sources` | Редактируемая связь T1–T9 с публикациями: методическая основа, определение метрики, пример дизайна или доказательство границы применимости. |
| `effect_checks` | Конкретная проверка эффекта, единица анализа и правило успеха. |
| `effect_check_conditions` | Роли условий: референс, база, кандидат, абляция или ассистирование. |
| `effect_check_data_types` | Данные, необходимые для проверки эффекта. |
| `effect_check_criteria` | Критерии, к которым применяется проверка. |

### Будущий операционный контур

| Таблица | Назначение |
|---|---|
| `experts`, `instructors`, `student_groups` | Только псевдонимные участники. Ключ соответствия хранится вне БД. |
| `lessons` | Псевдонимная единица занятия. |
| `dataset_splits`, `lesson_splits` | Калибровочная и независимая тестовая выборки. |
| `lesson_artifacts` | Метаданные и URI файлов; сами видео и документы в SQLite не сохраняются. |
| `evaluation_runs` | Запуск в конкретном условии. |
| `run_instruments`, `run_inputs` | Фактически использованные версии и артефакты. |
| `criterion_evaluations` | Балл либо отдельный статус отсутствия результата. |
| `evidence_fragments` | Цитата/описание, источник и таймкод. |
| `evaluation_reviews` | Независимая проверка, принятие или корректировка экспертом. |
| `effect_results` | Метрики, доверительные интервалы и размер выборки. |
| `criterion_decisions` | Версионируемое решение A–D о границе автоматизации. |

## Важные статусы

- `criterion_evaluations.result_status`: `scored`, `insufficient_data`, `error`, `not_applicable`. Только `scored` может иметь балл 0–2.
- `study_criteria.readiness_status`: `prototype_now`, `conditional`, `not_from_recording`.
- `study_criteria.platform_coverage_status`: `partial`, `indirect`, `not_covered`. Полного покрытия готовыми метриками нет.
- `instrument_version_criteria.validation_status`: `validated`, `unvalidated`, `not_documented`, `reference`.
- `research_sources.verification_status`: `to_review`, `source_register_checked`, `user_verified`, `partially_verified`, `not_verified`.
- `criterion_research_sources.relevance_status`: `to_review`, `confirmed`, `partially_confirmed`, `rejected`.
- `verification_method_research_sources.relation_role`: `methodological_basis`, `metric_definition`, `design_example`, `boundary_evidence`.
- Решения A–D: автоматизируемо; только поддержка эксперта; нужен дополнительный контекст; не определяется по записи.

## Правила работы с данными

1. Идентификаторы преподавателей, экспертов и групп — псевдонимы; ФИО не сохраняются.
2. Медиа и документы хранятся во внешнем защищённом хранилище, в БД — URI, checksum, качество и режим доступа.
3. Для критериев 24 и 25 нужны прямые студенческие данные: соответственно exit ticket/результаты до–после и валидированный опрос доверия.
4. Эмоции и взгляд не трактуются как внимание, доверие, успех или психологическая безопасность; доля речи не равна качеству диалога.
5. `Eval-2024` зарегистрирован как историческая неподтверждённая версия. Существующие отчёты по 17 занятиям не импортированы.
6. Секреты и токены из исходного notebook в БД и сопровождающие файлы не переносятся.
7. Дата `registry_checked_on` перенесена из исходного литературного реестра и сама по себе не означает пользовательскую верификацию. Для собственной проверки меняются `verification_status`, `relevance_status`, `supported_claim`, `source_locator` и `notes`.
8. Источники S36–S47 подобраны как методическая опора для T1–T9 и имеют статус `to_review`, пока пользователь не проверит их применимость к пилоту.

## Представления

- `v_criterion_scale` — плоские 78 строк шкалы.
- `v_instrument_coverage` — покрытие критериев версиями инструментов.
- `v_condition_matrix` — инструменты и данные A0–A5.
- `v_effect_check_plan` — эффекты, методы, сравнения, источники данных и связанная литература.

## Воспроизведение

Создать новую БД можно последовательным выполнением `Схема базы пилота.sql`, затем `Начальные данные базы пилота.sql` в пустом SQLite-файле с включённым `PRAGMA foreign_keys = ON`.
