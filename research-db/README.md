## Что переносится

Сборщик сохраняет все 39 таблиц широкого дизайна и все 52 таблицы mgpu-only как неизменяемые снимки строк, схем и происхождения. Оба дизайна имеют отдельные нормализованные рубрики, методы, эффекты и научные связи. Их A-коды сохраняются внутри исходных снимков и не переиспользуются с новым смыслом. Новый дизайн содержит полные старые T1–T9 и проверки E1–E9; изменения библиографии и содержательные проверки добавлены отдельным слоем. Исторические DB открываются только для чтения и сверяются по SHA-256.

`МА/МV` в матрице представлен отдельным неопределённым условием `MA/MV`, не готовым объединённым обработчиком. Реальные MA, MV и MA-MV имеют отдельные условия. T-ROLE/T-TIMED/T-CTX-LONG описывают дополнительные требования к данным, а не реализованные отдельные модели. Каждая пара указывает изменяемый компонент, контроль и необходимые входы; доступность пары ещё предстоит подтвердить на пробе.

## Построить новую БД

Python 3.10+ и стандартная библиотека. Вторая исходная БД предоставляется отдельно как SRC-10. Из корня репозитория:

```sh
python3 planning/combined-pilot/audit/continue_audit.py
python3 research-db/build.py --mgpu-db /path/to/mgpu-only.sqlite --output /path/to/new-combined.sqlite
python3 research-db/verify.py --database /path/to/new-combined.sqlite --mgpu-db /path/to/mgpu-only.sqlite
python3 -m unittest discover -s research-db -p 'test_*.py'
```

Существующая исследовательская БД не перезаписывается сборщиком. Для новой версии используется новый файл. `verify.py` проверяет точные исходные строки, полные тексты методов, целостность, внешние ключи, 26/78/36/41/137 и round-trip SQL → SQLite. Файл `.manifest.json` относится к исходной сборке; после операционного импорта актуальные SHA и счётчики находятся в `verification.json`.

## MODEUS и внешние ID

[sampling.py](sampling.py) готовит детерминированную проверку выполнимости 2 дисциплины × 2 преподавателя × 2 команды и резерв. Это технический отбор, не случайная выборка и не подтверждение записи. Общий event ID нельзя считать двумя независимыми занятиями. Время имеет явное смещение UTC; просроченные/отменённые события исключаются. Для первой реализации предполагаются четыре разных преподавателя и четыре разных команды внутри каждой дисциплины; если методический план изменится, понадобится новая версия правила.

```sh
python3 research-db/sampling.py --analysis /path/to/analysis.json --source-captured-at 2026-10-06T01:00:00+05:00 --as-of 2026-10-06T02:00:00+05:00 --output /path/to/local-selection
python3 research-db/import_modeus.py --database /path/to/new-combined.sqlite --analysis /path/to/analysis.json --selection /path/to/local-selection/selection.json
```

Снимок старше суток отклоняется без явного `--historical-preview` на обоих этапах. Сутки — инженерное правило осторожности для подготовки, не утверждённая гарантия свежести расписания. Перед записью всё равно нужна новая проверка события и помещения. Историческое preview имеет `stale=true`, все занятия остаются `candidate`. Импорт сверяет SHA и пересчитывает выборку; повтор того же снимка не дублирует строки, новый снимок получает отдельные версии сущностей. Ключ — namespace + external kind + external ID + snapshot, не ФИО.

Экспертная платформа пока не подключена. Контракт: её lesson/media/assignment/rubric/AIResult ID, версия и SHA связываются через снимок и внешние ссылки; режим и закреплённый AI run контролируются сервером платформы. Ограничение SQLite на EXP-AI предотвращает случайную потерю pin, но не заменяет серверную защиту слепого режима. Точный формат экспортного файла и проверка на реальном экспорте остаются DATA-02.

## Доказательства и статусы

- `scored` требует балла 0–2. `insufficient_data`, `not_applicable`, `error`, `invalid_output` требуют NULL вместо балла.
- Численная confidence требует определения смысла; её отсутствие сохраняется NULL. Без вероятностной уверенности ECE не вычисляется.
- Символьные локаторы — полуинтервалы `[start_char,end_char)` по неизменённому тексту, кодовые точки Unicode Python. Таймкоды — реальные миллисекунды. Границы обязаны помещаться в артефакте известной длины/длительности. Quote ещё нужно сверить с файлом соответствующего SHA; одна SQL-ссылка не доказывает корректность цитаты.
- Артефакты, результаты, назначения и прогоны обязаны принадлежать одной версии/занятию; повторы закрепляют модель/prompt/config. Калибровочный и тестовый split держат преподавателя целиком; группы студентов, общие между преподавателями, потребуют дополнительного контроля зависимости.
- Метрики сохраняют исходное число, единицу, участок, знаменатель с происхождением и версию преобразования. Частоты не становятся баллами автоматически.

## Видимость и производные файлы

DB, полный SQL, словарь, снимки MODEUS и операционные формы хранятся локально. `.public.json` включает только разрешённые столбцы замысла; новые таблицы отклоняются до назначения политики. Внутренние ID, люди, события, медиа, назначения, ответы и результаты не экспортируются. Даже таблицы дизайна не экспортируют исходные JSON со служебными путями.

`prepare_trial.py --output /path/to/forms` создаёт шесть технических профилей, формы QC/времени/критериев для двух записей и арифметические сценарии 8/12/16 оценок. Оценки, цены, скорости и трудозатраты не подставляются.

## Ещё требуется

Действующая модель Eval-2024 без старых Coze-доступов, реальная проба двух записей, спецификации/экспорт МГПУ, завершение литературных оснований, свежий MODEUS, подтверждение записи/экспертов, численные QC-пороги и бюджет, адаптированные прямые данные C24/C25, очное наблюдение и расширение выборки. Финальный протокол и независимый тест не объявлены готовыми. Просмотрщик новой БД и трёхминутный HTML — последующие этапы.

## Маркировка авторства 07.10.2026

Реестр AI хранится рядом с моделью как версия документации 1.4. SQLite-снимок от 06.10 не переписывается ради пометок: его научные данные и хеш сохраняются. При следующей содержательной версии БД включить актуальные метаданные авторства аудита и ссылку на реестр; D-17 не утверждает AI-методику.
