# Eval-2024: минимальная подготовка к пилоту

Это продолжение нашего инструмента из `class_feedback.ipynb`, подтверждённого пользователем 05.10.2026. Сохранён подход: отдельный запрос в тот же Coze bot для каждого критерия, исходная рубрика 0–2 и текстовое обоснование. Исторический notebook и его отчёты не заменяются.

Минимальные изменения вынесены в небольшой проверяемый Python-файл: полный транскрипт без обрезания, отказ и ошибка отдельно от нуля, строгий диапазон балла, точные цитаты с проверкой наличия в тексте, сохранение исходных ответов и версий. Сумма частичных оценок и дополнительная генерация общих рекомендаций не используются как исследовательский результат.

Цитаты привязаны к символам исходного текста (Unicode code points), включая все повторные вхождения. Без временной разметки транскрипта таймкоды остаются пустыми. Такой JSON ещё не равен импорту экспертной платформы, которая требует временных интервалов. Не подставлять символы вместо миллисекунд.

## Проверка без внешнего запроса

Из корня проекта:

```sh
python3 -m unittest discover -s transcript-eval/tests -v
python3 transcript-eval/eval_2024.py --transcript /путь/занятие.txt --output transcript-eval/var/probe-prompts.json --dry-run
```

Dry-run сохраняет полный набор промптов локально; Coze не вызывается. Без `--checklist` рубрика читается из исторической SQLite в режиме read-only. Можно передать исходный `--checklist /путь/checklist.csv`; файл проверяется на 26/78 без угадывания отсутствующих шкал.

## Запуск существующего Coze bot

Установить `requirements.txt` в отдельное Python-окружение. Указать `COZE_API_TOKEN`, `COZE_BOT_ID`, `COZE_USER_ID`, фактическую `COZE_MODEL_VERSION`; при необходимости — `COZE_API_BASE`. Идентификаторы и токен не записывать в публичные файлы. По умолчанию используется `https://api.coze.com`, как в исходном notebook.

```sh
python3 transcript-eval/eval_2024.py --transcript /путь/занятие.txt --output transcript-eval/var/run-01.json
```

Один запуск сохраняет JSON и Markdown с исходными ответами. Для повтора выбирать новое имя: прежний прогон не перезаписывается. Если полный вход превышает доступный контекст бота, это ошибка запроса; автоматического усечения или агрегации кусков в этой минимальной версии нет. Параметры самого бота, модель и предел контекста нужно зафиксировать до пробы.

Статусы: `scored` — экспериментальный балл с найденной цитатой; `insufficient_data` — отказ из-за недостаточных данных; `invalid_output` — некорректный ответ/балл/цитата; `error` — запрос не выполнен. Каждый результат имеет `validation_status: candidate`: наличие цитаты не доказывает соответствие критерию.

Локальные тесты и dry-run подтверждают работу оболочки. Реальный запрос, доступность bot и качество на двух записях проверяются отдельной пробой; они ещё не подтверждены. Все входы/результаты в `var/` остаются локальными.

API сверено с [официальным примером Coze](https://github.com/coze-dev/coze-py/blob/main/examples/chat_no_stream.py); зависимость зафиксирована как `cozepy==0.20.0` по PyPI на дату проверки.
