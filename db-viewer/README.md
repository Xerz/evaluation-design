# Навигатор БД пилота ТюмГУ

Локальный интерфейс для просмотра и, по явному флагу, редактирования существующей SQLite-базы пилота автоматизации критериев оценки преподавателя.

## Запуск

Из корня проекта:

```bash
python3 db-viewer/server.py
```

Открыть: <http://127.0.0.1:8000>

Дополнительные параметры:

```bash
python3 db-viewer/server.py --port 8080
python3 db-viewer/server.py --db "/полный/путь/к/базе.sqlite"
python3 db-viewer/server.py --open
```

Сервер всегда привязывается только к `127.0.0.1`. SQLite открывается через `mode=ro` и `PRAGMA query_only=ON`.

## Редактирование

Включить локальные формы записи:

```bash
python3 db-viewer/server.py --edit --open
```

В этом режиме доступны добавление, изменение и удаление строк всех 39 таблиц. Четыре представления остаются только для чтения. Первичные ключи существующих строк не меняются, внешние ключи выбираются из связанных справочников, а `NULL` задаётся отдельно от пустой строки и нуля.

Перед первой подтверждённой записью каждого запуска создаётся согласованная резервная копия. Бэкапы и журнал изменений находятся в `db-viewer/var/`, исключены из Git и не попадают в статический сайт. Удаление строк с зависимостями требует ввода имени таблицы.

Рабочая SQLite является актуальным источником. Исходные schema/seed SQL автоматически не переписываются. Выгрузить полное текущее состояние в локальный SQL-снимок можно командой:

```bash
python3 db-viewer/export_sql.py
```

Публичный снимок после локальных правок не пересобирается и не публикуется автоматически.

## Разделы

- обзор контрольных количеств и состояния пилота;
- 26 критериев со шкалой 0–2 и связанными данными;
- 47 исследовательских источников, 111 связей с критериями и 24 связи со способами проверки;
- версии инструментов и покрытие критериев;
- условия A0–A5 и эффекты E1–E9;
- масштабируемая ERD;
- технический просмотр всех таблиц и представлений SQLite.

Интерфейс не содержит SQL-консоли, изменения схемы или импорта произвольных файлов. Методы записи включаются только флагом `--edit` и защищены проверкой локального источника и сессионным CSRF-токеном.

## Статическая сборка и GitHub Pages

Собрать снимок SQLite в корневой каталог `docs/`:

```bash
python3 db-viewer/build_static.py
```

Проверить его локально:

```bash
python3 -m http.server 8001 --directory docs
```

Открыть: <http://127.0.0.1:8001>

Статическая версия не содержит Python-сервера и читает заранее экспортированные JSON-файлы. Все пути относительные, поэтому сайт работает как в корне домена, так и по адресу вида `https://<owner>.github.io/<repository>/`. Hash-маршруты сохраняются.

Workflow `.github/workflows/pages.yml` пересобирает снимок из SQLite и публикует артефакт через GitHub Pages после push в `main` либо ручного запуска. В настройках репозитория нужно один раз выбрать **Settings → Pages → Source: GitHub Actions**.

Справочники и исследовательский дизайн публикуются полностью. Строки и реальные количества операционных таблиц — занятия, участники, артефакты, запуски, оценки, доказательства и результаты — в Pages не экспортируются; вместо них показывается статус «Доступно только в локальной базе».

После изменения SQLite публичный сайт обновится только после отдельной сборки и push либо запуска workflow.

## Проверка

```bash
python3 -m unittest discover -s db-viewer/tests -v
```

Тесты проверяют контрольные количества, read-only режим, CRUD на временной копии SQLite, одиночные и составные ключи, FK/CHECK/JSON, конфликт версий, бэкап, журнал, безопасное удаление, HTTP API и приватность статического экспорта.
